## Reduced models and sign conventions

The new COM angle is **from upward vertical**:

```
r = COM - projected_front_foot_midpoint
theta = atan2(r_x, r_z)
theta_dot = (r_z * relative_v_x - r_x * relative_v_z) / l²
l = sqrt(r_x² + r_z²)
l_dot = (r_x * relative_v_x + r_z * relative_v_z) / l
```

A COM behind front support has negative theta. Positive theta velocity toward
zero and positive generalized torque have world +y sign, matching positive
body-pitch rotation. Gravity is `+m*g*l*sin(theta)` and opposes the approach from
negative theta. Body pitch is measured independently from the base orientation;
it is not theta. The prior report's downward-vertical COP-based angle is retained
in raw diagnostics under its old name and is not substituted into this equation.

The pivot is the midpoint of the two front-foot geometry centers projected onto
the flat ground. Its measured motion is subtracted from COM velocity; measured
pivot acceleration enters conditional inverse dynamics. This reduces the
force-weighted COP jumps in the previous approximation. It remains approximate:
moving/rolling feet and distributed contacts are not a fixed material hinge.
Foot-center tangential speed and displacement are conservative slip/motion
proxies, not a direct measurement of every contact patch's tangential slip.

Implemented models, in increasing complexity:

1. Fixed length: `J=m*l0²`, `J_dot=0`.
2. Variable point mass: `J=m*l²`, `J_dot=2*m*l*l_dot`, exactly the requested
   variable-length equation with the stated convention.
3. Configuration inertia: `J=I_COM,y(q)+m*l²`,
   `J_dot=I_COM,y_dot+2*m*l*l_dot`.

For a flat moving pivot:

```
J*theta_ddot + J_dot*theta_dot
    = m*g*l*sin(theta) + tau_eff - m*r_z*pivot_acceleration_x
```

I_COM,y sums each link's rotated inertia and parallel-axis contribution. It is
not just trunk inertia. `tau_eff` is identified from smoothed measured motion
and this balance, then fitted to current COM state, inertia and six grouped
joint-action inputs using regularized linear regression. No summation of motor
torques is treated as a directly actuated pendulum input.

An independent diagnostic decomposes generalized torque using ground-contact
moment about the pivot and the derivative of articulated shape momentum:

```
shape_momentum = H_COM,y - I_COM,y*theta_dot
tau_eff ≈ contact_moment_about_pivot - d(shape_momentum)/dt
```

All motor joint positions, velocities and torques, COM state, body pitch/rate,
front/rear ground reactions, contact moments, inertia and foot motion are saved
at the 2 ms physics rate. Numerical differentiation uses an 11-sample smoothing
window. Derivative ground truth uses surrounding samples; it is not an online
state estimator. Differentiation/contact uncertainty is reported rather than
interpreted as exact articulated dynamics.

## Held-out model validation

Identification uses only the three development resets per policy (172 eligible
samples for seed 42 and 190 for seed 43). Eligibility requires both front feet
loaded, rear feet unloaded, no collision/limit violation, foot-center speed
below .05 m/s, drift below .04 m, and an 11-sample guard around transitions.

One-step validation is explicitly **conditional on measured current state and
estimated support acceleration**. It is distinct from the 100 ms forecasts,
which use only the initial state and recorded commanded-action sequence. Those
forecasts do not read future measured COM, length, inertia, torque or pivot
acceleration. Variable models forecast radial motion; the complete model also
forecasts inertia rate. Fixed-pivot forecasts intentionally omit unknown future
pivot acceleration. A unit test changes future measured states and verifies
that these predictions do not change.

Mean held-out one-step acceleration RMSE across the original-policy rollouts:

| Model | COM angular acceleration RMSE (rad/s²) |
|---|---:|
| Fixed length | .103 |
| Variable length | .036 |
| Configuration-dependent inertia | .116 |

For eligible 100 ms windows, mean per-window angle/rate RMSE is:

| Model | Angle RMSE | Angular-rate RMSE |
|---|---:|---:|
| Fixed length | .389° | .233 rad/s |
| Variable length | .153° | .087 rad/s |
| Configuration inertia | .096° | .061 rad/s |

**These 100 ms windows exist only for policy seed 42.** Seed 43 has no continuous
100 ms interval satisfying the predefined eligibility mask. Its missing forecast
is shown explicitly, not replaced with a fabricated curve or a relaxed mask.
The one-step table includes both seeds. CSV files contain individual rollouts,
window counts and clamping counts; no reported eligible forecast required clamps.

These good short local fits do not validate large controlled action changes.
Frozen models were also tested on 40 changed-action runner-up rollouts without
refitting. Mean acceleration RMSE rises to roughly 1.78/2.31/1.53 rad/s² for
fixed/variable/configuration models. Only about 3.55 eligible samples per such
rollout remain on average, and **no 100 ms changed-action window is eligible**.
Most of the interesting rotation occurs near contact transitions, outside the
well-identified regime. Grouped actions also omit left/right asymmetry and much
of the articulated configuration. These are limitations of the model and data,
not evidence that the identified torque is a freely available actuator.

## Reference generation and full-dynamics refinement

Quintic initial proposals preserve measured body pitch/rate **and independently
measured COM angle/rate and length/rate**; all terminal rates/accelerations are
zero after a .3 s approach followed by a hold. Independent COM initialization is
essential: body angular rate is not multiplied by a gain and used as COM rate.
The proposed length shortens by .01 m. Inverse dynamics produces fixed/variable/
configuration-inertia effective-torque requirements for these proposals.

The empirical COM-angle/body-pitch gain is poorly identified, especially seed
42 where the local regression has negative slope. A conservative positive gain
for the forward COM proposal is recorded separately from the observed gain.
That is an explicit heuristic for a candidate, not a physical equivalence of
the two angles or a validated body-to-COM map. The required torque curves extend
well beyond the identified effective-torque envelope, as documented in
`figures/reference_torque_envelope.csv`. Thus these initial proposals are not
declared physically feasible from the reduced model alone.
For the configuration-inertia proposals, required effective torque spans roughly
16.2–35.0 N m, while the original-policy identification envelopes span only
about −1.8 to +8.2 N m. Every proposed reference sample lies outside its fitted
torque envelope. This is a serious extrapolation warning, not a measurement of
the robot's absolute motor-torque capability.
The proposed terminal COM angle also remains approximately −.5 rad from upright
while its requested COM rate tends to zero. That is not a gravity-balanced
point-pivot terminal state. It demands sustained generalized torque that cannot
be assumed available from internal joint motors. This is a concrete failure of
the present COM/body reference construction, not something PPO should be asked
to repair blindly. A better next step is a full-model terminal-posture solve
with COM/support geometry, calf clearance and native torques constrained, then
connection of that posture to the valid takeoff state. Merely mapping body
pitch to COM angle by a local gain is inadequate here.

Full MuJoCo finite-response samples initialize **joint action residuals**, then
CEM refines them. There are no gradients through contact. Five interpolated
knots × 12 joint actions give 60 search variables; each candidate receives three
development resets. Four generations × 20 candidates × two policy seeds produce
**480 scored full-MuJoCo cases**. The maximum horizon is .7 s (35 control steps),
with native termination/limits active. Ranking penalizes pitch/rate and COM/length
tracking error, front sliding/motion, contact loss, inappropriate contact moments,
command changes and collision/native-state violations. Braking near the target
is not indiscriminately penalized. A constant-target holding candidate and the
original policy are included as controls.

Only the training-score winner (rank 0) is confirmatory. Runners-up ranks 1/2
are disclosed exploratory diagnostics on the same ten validation resets; none
can override the preselected gate. The original policy is evaluated on exactly
the same saved start/reset family. Optimized controls are saved for offline
analysis; no separate controller is deployed and no CPG is introduced.

Gate, specified before the definitive search:

- Reach at least 45° while `abs(pitch_velocity)<=.5 rad/s`.
- Remain within 40–50° with that speed bound and both front feet loaded for
  .3 continuous seconds.
- No front-contact gap exceeding .02 s, no nonfoot/self collision, no native
  joint/velocity/effort violation.
- Foot-center motion/slip proxy integral <=.02 m and front drift <=.04 m.
- At least 8/10 successes for each seed's preselected reference.

## Actual feasibility result and mechanism

All 480 development cases fail the complete gate. The largest development peak
is **44.989°**, and the longest low-speed in-band duration is **.050 s**, not
.3 s. Rounding that peak to 45° must not be interpreted as success.

Both confirmatory candidates are safe constant-target settling solutions:
mean peak is about 32.81° for seed 42 and 32.04° for seed 43. They reach neither
the target nor its hold. Their 20 robustness cases have **0 successes**, despite
retained front contact and native state validity. All 40 exploratory runner-up
cases also fail; some achieve greater rotation but collide before a sustained
controlled hold. Example replays identify FL_calf ground contact for seed 42 and
FR_calf ground contact/front-contact loss for seed 43. See
`failure_diagnostics.csv` and `constraint_examples.json`.

Failed runner-up rollouts reach the native effort envelope, but observed speed
ratios remain below one and joint limits are not exceeded. Therefore the directly
observed failures are contact/clearance and terminal-control failures, not a
demonstrated velocity or joint-range hard limit. Opposing front moments and
changing articulated configuration remain important; increasing an imaginary
pendulum torque does not resolve the native contact trajectory. Finite CEM
coverage is also limited in 60 dimensions. This is **not a proof that Go2 cannot
perform the maneuver**, nor that no better joint-level optimizer could find it.

No robust demonstration is accepted for imitation. The original successful
CPG-free takeoff actor is not replaced.

## Prepared task and learning path

`gym/envs/go2/go2kickup_pendulum.py` supplies the opt-in
`go2kickup_pendulum` **CPU research-task registry** and configuration. It preserves
44/74 observations and the 12-action interface. It deliberately does not alias
the incompatible GPU `LeggedRobot` registry or claim compatibility with
`scripts/train.py --task ...`. Use the supplied CPU runner.

When—and only when—physical reference validation passes, the prepared path:

1. Restores each verified fixed/global actor, critic, Adam and RNG, checks
   architecture/control compatibility, and keeps the source checkpoints intact.
2. Fits a copy of the actor for 120 BC updates on successful reference frames
   mixed with the original takeoff-prefix data. The baseline receives no new
   reference imitation; this deliberate offline-data difference is logged.
3. Uses a staged controlled-success curriculum: near transition, nearby resets,
   longer approach, then standing. Two 32-episode windows with >=80% controlled
   success and a minimum stage budget are required; takeoff alone never advances.
4. Runs matched A/B two-iteration PPO smoke tests, then six further updates,
   with identical evaluation resets and 1,024 transitions per update/condition/
   seed. Full completion would be 32,768 PPO interactions across both methods
   and seeds, of which 8,192 are smoke interactions. There is no extended launch.
5. Evaluates standing-start deterministic/stochastic behavior and stops pairs
   for takeoff regression, excessive KL or clipping; checkpoints retain all
   optimizer/curriculum/simulator/RNG state.

Reference rewards retain the takeoff objectives and add terminal-corrected
reference-potential tracking, controlled holding, slip/contact penalties and
native failure costs. The compatibility/environment and gate logic are unit
tested. **The positive-gate BC/PPO path was not empirically exercised**, because
no feasible reference passes the required gate. No learning or improvement is
claimed from that prepared path.
